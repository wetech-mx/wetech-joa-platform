# CRM Call Center V0.6.0 — Conector Banco Azteca

## Alcance

Esta versión porta al backend Node.js el flujo validado en
`BancoAztecaDownloader`:

1. Solicitar token OAuth 2.0 mediante `client_credentials`.
2. Solicitar `idAcceso` y llave privada temporal.
3. Consultar campañas por fecha.
4. Descargar todas las páginas de clientes.
5. Descifrar campos RSA OAEP SHA-256.
6. Crear un Excel de 34 columnas.
7. Entregar el archivo al navegador sin almacenarlo en el servidor.

## Variables del servidor

Estas variables deben agregarse localmente a `/opt/crm/backend/.env`.
Nunca deben enviarse por chat ni guardarse en Git.

```dotenv
BAZ_BASE_URL=https://URL-OFICIAL-DEL-BANCO
BAZ_CONSUMER_KEY=CONFIGURAR_EN_EL_SERVIDOR
BAZ_CONSUMER_SECRET=CONFIGURAR_EN_EL_SERVIDOR
BAZ_ID_DESPACHO=CONFIGURAR
BAZ_ID_ESTATUS=CONFIGURAR
BAZ_ID_CANAL_ENVIO=CONFIGURAR
BAZ_TIMEOUT_MS=30000
BAZ_MAX_PAGES=5000
```

El token de acceso no se configura: el conector lo solicita en cada
ejecución.

## Rutas

Todas las rutas requieren JWT, rol Administrador o Super Admin y una
empresa válida.

| Método | Ruta | Finalidad |
|---|---|---|
| GET | `/api/banco-azteca/estado` | Indica si faltan variables, sin mostrar valores |
| POST | `/api/banco-azteca/exportar` | Descarga el Excel para una fecha |

Solicitud:

```json
{
  "fecha": "2026-07-27"
}
```

## Controles de seguridad

- HTTPS obligatorio para la URL bancaria.
- Timeout por petición.
- Reintentos limitados para `429` y errores temporales `5xx`.
- Límite máximo de páginas.
- Respuestas bancarias y tokens excluidos de los mensajes de error.
- Descifrado estricto; un fallo detiene la exportación.
- Neutralización de fórmulas en celdas de texto.
- Excel generado en memoria, sin archivos residuales.
- Dependencias de producción auditadas sin vulnerabilidades conocidas.

## Verificaciones

```bash
cd /opt/crm/backend
npm ci
npm run check
npm test
npm audit --omit=dev

cd /opt/crm/frontend
npm ci
npm run build
npm audit --omit=dev
```

Las llamadas reales al banco deben ejecutarse únicamente después de:

1. Confirmar la IP pública autorizada.
2. Confirmar si las credenciales corresponden a sandbox o producción.
3. Registrar las variables en el servidor.
4. Realizar una primera descarga con fecha y volumen controlados.
